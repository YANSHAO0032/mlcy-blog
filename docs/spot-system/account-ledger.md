# 账户资金与流水一致性：负责人首先要守住资损底线

## Problem

现货系统里，最严重的问题通常不是接口报错，而是钱解释不清楚。账户资金一旦出现重复扣减、漏入账、错误解冻、手续费算错、返佣重复，影响就会从功能故障升级为资损风险。

负责人必须能回答这些问题：

- 这笔钱为什么变了？
- 是哪笔订单、成交、撤单或运营动作触发的？
- 变化前后余额是多少？
- 这个动作有没有重复执行？
- 如果中途失败，能不能补偿？
- 余额、流水、快照、报表能不能对上？

## 资金模型

现货账户至少要拆成两类模型：

```text
账户余额模型：表达当前状态
资金流水模型：表达变化原因和证据链
```

余额解决“现在有多少”，流水解决“为什么变成这样”。

### 1. 账户余额不是一个数字

在交易系统里，一个账户通常不能只用 `balance` 表达全部语义。常见资金状态包括：

- 可用余额
- 冻结余额
- 可提现余额
- 活动赠金
- 手续费账户
- 平台收入账户
- 返佣或分润账户

不同状态背后的业务含义不同。负责人要避免所有资金动作都用简单加减表达，否则后面无法判断这笔钱到底是交易冻结、成交扣减、手续费还是运营奖励。

### 2. 资金流水是审计核心

每笔资金变化至少应该具备：

- from account
- to account
- amount
- scene
- refType
- refId
- fromBalance
- toBalance
- fingerprint 或幂等标识
- 操作时间和操作人

流水不是附属日志，而是资金系统的证据链。没有流水，余额正确也只是暂时看起来正确。

### 3. 双账户转账要有固定锁顺序

现货交易里的资金动作经常是双账户或多账户转移，例如：

- 用户可用账户 -> 用户冻结账户
- 用户冻结账户 -> 对手方可用账户
- 用户账户 -> 平台手续费账户
- 平台手续费账户 -> 代理返佣账户

为了降低死锁风险，账户锁定顺序应该稳定，比如按账户类型或账户 ID 排序后加锁。不能让两个并发事务以相反顺序锁账户。

### 4. 批量资金动作也要保留单笔证据

为了性能，系统可以批量更新账户余额、批量写入历史快照。但每一笔业务资金动作仍然要有独立流水和快照。否则性能提升会牺牲排障能力。

负责人要关注：

- 批量更新是否在同一事务里
- 每笔 transaction 是否有 refType/refId
- 历史快照是否记录扣减方和入账方
- 批量失败时是否整体回滚

### 5. 幂等不是补丁，是资金系统基础设施

资金事件会重复出现：

- 上游重试
- MQ 重复投递
- 消费者重启后回放
- 人工补偿再次执行
- 对账任务补单

所以资金变化必须绑定唯一业务键。典型做法是：

- 业务单号 + 动作类型形成幂等键
- 流水表或幂等表加唯一约束
- 账户更新和流水落库在同一事务内完成

同一成交或同一撤单事件重复消费时，资金结果必须只生效一次。

## 常见资金场景

### 下单冻结

买单通常冻结计价币，卖单通常冻结基础币。

```text
available - amount
frozen + amount
```

重点是冻结金额要和订单价格、数量、费率预估边界一致。

### 成交扣减与入账

成交后需要处理：

- 扣减冻结资产
- 买方入账基础币
- 卖方入账计价币
- 扣 maker / taker 手续费
- 写成交流水和资金流水

这里最怕“成交状态成功，但资金没处理完”。订单和资金必须能通过成交 ID 对齐。

### 撤单解冻

撤单不是简单把订单剩余数量改成取消，还要释放未成交部分冻结资产。

```text
frozen - remain
available + remain
```

撤单与成交并发时，要以撮合最终回报为准，避免多解冻。

### 手续费和返佣

手续费通常是资金链路的一部分，返佣则更适合作为旁路结算：

- 手续费扣减要和成交入账保持清晰关系
- 返佣可以消费手续费或成交事件异步计算
- 返佣失败不应影响主交易完成
- 返佣必须可重算、可补偿、可审计

## 对账视角

成熟资金系统至少要能做四层对账：

- 余额表：当前资产状态
- 流水表：每笔资金变化
- 业务单据：订单、成交、撤单、充值、提现、返佣
- 汇总报表：日维度、币种维度、平台维度

对账发现差异时，不应该直接改余额，而应该定位差异来源，再通过补偿流水修复。

## 负责人检查清单

- 所有资金变化是否有业务单号和流水。
- 账户更新和流水落库是否在同一事务边界内。
- 同一业务事件重复执行是否只生效一次。
- 双账户或多账户更新是否有固定锁顺序。
- 成交、撤单、手续费、返佣是否有不同流水类型。
- 批量更新是否仍能保留单笔证据。
- 对账差异是否能通过补偿流水修复，而不是人工改余额。
- 主从延迟是否会影响资金读取和更新。

## Summary

账户资金系统的第一目标不是快，而是永远能解释钱为什么变化。负责人要把账户余额、资金流水、历史快照、幂等、锁顺序、事务边界、对账和补偿组织成一套可信基础设施。这样系统出问题时，团队不是靠猜，而是靠证据恢复。
