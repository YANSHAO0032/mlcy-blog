# 币对生命周期与上币流程：上币不是新增配置，而是一次系统发布

## Problem

很多人把上币理解为“后台加一个交易对”。但真实现货系统里，一个币对从准备到开放交易，会牵涉多个系统：

- 币种配置
- 交易对配置
- 账户类型
- 钱包充值提现
- 撮合节点
- 行情订阅
- 费率配置
- 风控限额
- 白名单灰度
- 运营后台
- OpenAPI
- 对账报表

任何一个环节漏掉，都可能造成交易不可用、行情异常、用户无法充值、手续费错误、风控失效或运营无法管理。

## 生命周期

一个交易对的生命周期可以拆成：

```text
准备
-> 灰度
-> 预热
-> 开放交易
-> 运营调整
-> 暂停交易
-> 下线或迁移
```

负责人要把上币当成跨系统发布，而不是后台表单。

## 核心配置

### 1. 币种配置

币种配置影响：

- 币种符号
- 精度
- 链类型
- 充值提现开关
- 最小充值提现数量
- 手续费
- 钱包地址生成
- 风控策略

如果币种本身配置不完整，交易对开放后也会出现资产侧问题。

### 2. 交易对配置

交易对配置影响：

- base / quote
- symbol 名称
- 是否开放
- 价格精度
- 数量精度
- 最小下单数量
- 市价单开关
- 排序和首页展示
- 撮合集群绑定
- 白名单和灰度策略

这些配置决定用户能不能交易，以及订单能不能正确进入撮合。

### 3. 账户类型

新币种或新交易对通常需要创建相关账户类型：

- 用户现货账户
- 冻结账户
- 平台手续费账户
- 特殊业务账户
- 返佣或分润账户

账户没有准备好，交易链路即使能下单，也可能在资金处理阶段失败。

### 4. 费率和手续费

现货费率要和交易对绑定：

- maker fee
- taker fee
- VIP 费率
- 特殊用户费率
- 平台币抵扣
- 手续费币种

上币时要确认历史配置不会误套新币对，也要确认新币对的手续费能被报表和返佣系统识别。

### 5. 行情和撮合

币对开放前必须确认：

- 撮合节点已配置
- 行情服务能消费该交易对事件
- WebSocket 频道能订阅
- ticker、depth、kline 能生成
- 初始价格和价格保护配置合理

否则用户看到的市场状态会和撮合真实状态脱节。

## 上币流程建议

### 准备阶段

- 创建币种配置。
- 创建交易对配置但不开放。
- 创建账户类型和平台账户。
- 配置手续费、风控和限额。
- 绑定撮合集群。
- 配置行情和 WebSocket 频道。
- 准备运营后台权限。

### 灰度阶段

- 仅白名单用户可见。
- 小流量下单测试。
- 验证限价、市价、撤单、部分成交。
- 验证充值、提现、资金流水和手续费。
- 验证行情、K 线、深度和成交推送。

### 开放阶段

- 开放交易对状态。
- 开启前台展示。
- 打开 OpenAPI 可见性。
- 观察成交量、失败率、撮合延迟、行情延迟。
- 观察账户流水和手续费报表。

### 运营阶段

- 调整排序、标签和活动。
- 调整费率和限额。
- 监控异常交易和刷量。
- 做日终对账和报表校验。

## 风险点

- 交易对开放了，但撮合节点未配置。
- 前台展示了，但 OpenAPI 或 WebSocket 不可用。
- 账户类型缺失，导致资金冻结或入账失败。
- 市价单开关错误，造成异常成交。
- 精度配置错误，导致订单数量或价格被错误截断。
- 手续费配置遗漏，导致平台收入或返佣错误。
- 白名单灰度逻辑和前台展示逻辑不一致。
- 暂停交易只关了前台，API 仍可下单。

## 负责人检查清单

- 币种、交易对、账户类型、手续费、风控是否都已配置。
- 新币对是否绑定正确撮合集群。
- App、Web、OpenAPI、WebSocket 的可见性是否一致。
- 限价单、市价单、撤单、部分成交是否通过灰度验证。
- 资金冻结、成交入账、撤单解冻、手续费扣减是否有流水。
- 行情 ticker、depth、trade、kline 是否能正常生成。
- 上币操作是否有审计记录和回滚方案。
- 暂停交易是否同时覆盖前台、API、撮合和运营入口。

## Summary

上币是一场跨系统发布。负责人要关注的不只是交易对能不能显示，而是订单、撮合、账户、行情、费率、风控、运营、OpenAPI 和对账是否全部进入正确状态。把上币流程标准化，才能降低每次运营发布的系统风险。
