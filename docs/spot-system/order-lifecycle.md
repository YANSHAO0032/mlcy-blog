# 下单链路与订单状态机：订单能进撮合前，系统必须先证明它安全

## Problem

下单接口看起来只是创建一条订单，但真实现货系统里，一笔订单在进入撮合之前，需要跨过很多业务关口：

- 用户是否登录、冻结、实名认证受限
- API 签名和 IP 白名单是否通过
- 交易对是否开放或处于灰度白名单
- 限价单价格是否偏离过大
- 市价单是否被交易对限制
- 单日交易量、持仓上限和风控限额是否触发
- 手续费、VIP、平台币抵扣是否需要冻结快照
- 资金是否足够，是否需要冻结
- 订单是否已经落库，是否投递到撮合

负责人要关心的不是“接口返回成功”，而是订单状态、资金状态和撮合投递之间有没有清楚边界。

## 推荐链路

```text
请求进入
-> 鉴权与参数校验
-> 用户状态检查
-> 交易对配置检查
-> 价格、数量、精度校验
-> 限额与风控检查
-> 手续费规则快照
-> 资金冻结或预校验
-> 订单落库
-> 投递撮合
-> 等待成交或撤单回报
```

### 1. 接入校验：先判断请求是否值得进入业务层

接入阶段应尽早拒绝明显不合法的请求：

- 参数缺失
- 签名错误
- 时间戳过期
- API key 无效
- IP 白名单不匹配
- 用户未登录或交易被冻结

这部分失败不应该产生订单，也不应该触发资金动作。

### 2. 交易对校验：配置不是静态字典，而是业务开关

交易对配置至少影响：

- 是否开放交易
- 是否允许市价单
- 最小下单数量
- 价格精度和数量精度
- 是否只对白名单用户开放
- 是否接入某个撮合集群
- 是否启用网格、杠杆、ETF 等扩展能力

负责人要把交易对配置看成发布系统的一部分，而不是普通后台表单。

### 3. 价格保护：防止异常订单直接进入撮合

限价单通常要基于最近成交价或参考价格做价格区间保护。它解决的不是“用户不能亏钱”，而是防止：

- 前端或 API 参数错误
- 机器人失控
- 极端价格污染盘口
- 异常订单触发行情和风控连锁反应

价格保护失败时，订单应该在进入撮合前被拒绝。

### 4. 风控与限额：主链路里的最后一道业务闸门

常见检查包括：

- 单日交易量限制
- 单币对交易限制
- 用户持仓上限
- 交易对风险配置
- 黑名单、白名单、特殊用户限制
- 市价单开关和特殊来源订单限制

这类规则可以配置化，但要有操作审计。因为一次错误配置就可能直接影响用户交易或造成风险敞口。

### 5. 手续费快照：不要让成交后再猜规则

订单创建时应尽量固化和交易相关的费率上下文：

- maker fee
- taker fee
- 用户 VIP 等级
- 特殊费率
- 平台币抵扣开关
- 手续费币种

如果成交后再动态查询当前配置，历史订单会被未来配置污染，排查和对账都会变困难。

### 6. 资金边界：下单成功不等于资金最终完成

下单阶段通常需要冻结买入资金或卖出资产，但负责人要明确：

- 订单状态机属于订单系统
- 资金状态机属于账户系统
- 两者通过业务单号、成交事件和流水关联

不要把“订单已创建”“资金已冻结”“撮合已接收”“成交已入账”混成一个状态。

## 状态机思路

订单状态可以按下面方式理解：

```text
INIT
-> NEW / PENDING_MATCH
-> PARTIALLY_FILLED
-> FILLED
-> PENDING_CANCEL
-> CANCELED
-> REJECTED
```

关键点不是状态名字，而是状态推进的来源：

- 接入层只能创建初始订单或拒绝请求
- 撮合回报推进成交相关状态
- 撤单请求只能进入撤单中，最终结果仍要等撮合或订单服务确认
- 资金失败不能被简单伪装成订单成功

## 风险点

- 下单接口里同步做太多旁路逻辑，导致主链路变慢。
- 订单已落库但 MQ 投递失败，撮合没有收到。
- 撮合收到订单但订单表状态没有及时推进。
- 撤单请求已发出，但撮合已先成交。
- 手续费配置变更后，历史订单无法解释当时为什么这么收费。
- OpenAPI 和 App 下单逻辑分叉，导致规则不一致。

## 负责人检查清单

- App、Web、OpenAPI 的下单规则是否一致，差异是否明确。
- 每个拒单原因是否发生在正确阶段。
- 订单状态是否能表达“待撤单”“部分成交”“撮合拒绝”等中间态。
- 订单落库、资金冻结、撮合投递之间是否有补偿方案。
- 费率是否在下单或成交时形成可审计快照。
- 风控规则是否有配置审计、灰度和回滚。
- 价格保护是否能防止异常价格污染市场。

## Summary

下单链路的目标不是尽快插入一条订单，而是在订单进入撮合前完成必要证明：用户可信、交易对可交易、价格数量合法、风险可接受、资金边界清楚、费率上下文可追踪。只有这样，后续成交、资金、行情和返佣才有可靠基础。
